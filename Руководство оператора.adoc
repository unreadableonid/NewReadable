[#architecture]
== Архитектура системы

[#system-components]
=== Компоненты системы

*Центральный хаб (шлюз)*::
Устройство с ARM-процессором, выполняющее роль MQTT-брокера и координатора Zigbee 3.0 сети.

*Периферийные устройства*::
- Датчики (Zigbee/Z-Wave)
- Исполнительные устройства (Wi-Fi/Matter)
- Камеры (RTSP/ONVIF)

*Облачная инфраструктура*::
- AWS IoT Core для управления соединениями
- База данных TimescaleDB для телеметрии
- Redis для кэширования состояний

[#communication-protocols]
=== Протоколы связи

[listing]
.Стек протоколов
----
Уровень приложения: MQTT 3.1.1/5.0 с TLS 1.3
Транспортный уровень: WebSocket Secure (WSS)
Сетевой уровень: IPv6 с 6LoWPAN для устройств с ограниченными ресурсами
Физический уровень: Zigbee 3.0, Z-Wave 700 series, Wi-Fi 6
----

[#diagnostics]
=== Процедуры диагностики

[#connectivity-issues]
==== Проблемы с подключением

. *Проверить статус устройства* в Zabbix/Grafana dashboard
. *Анализировать MQTT-логи* на предмет последней активности
. *Верифицировать сетевую доступность*:
+
nmap -p 8883 <device_ip>
mosquitto_pub -h <broker> -t "device/status" -m "ping"

. *При необходимости выполнить репартиционирование* в Zigbee сети

[#performance-issues]
==== Проблемы производительности

*Высокая загрузка CPU*::
- Проанализировать количество retained messages в MQTT
- Проверить частоту публикации телеметрии

*Проблемы с latency*::
- Измерить RTT до AWS IoT Core
- Проверить QoS levels в MQTT (использовать QoS 1 для critical commands)

[#maintenance]
=== Плановое обслуживание

[#firmware-updates]
==== Обновление прошивок

[source,python]
----
# Скрипт массового обновления OTA
import asyncio
from device_manager import FirmwareManager

async def batch_update(devices: List[str], fw_version: str):
    async with FirmwareManager() as fm:
        tasks = [fm.update(device, fw_version) for device in devices]
        await asyncio.gather(*tasks, return_exceptions=True)
----

[#backup-procedures]
==== Процедуры резервного копирования

. *Конфигурация устройств*: Ежедневный экспорт в S3 bucket
. *Пользовательские сценарии*: Репликация в standby регион
. *База данных состояний*: Point-in-Time Recovery с retention 30 дней

[#troubleshooting]
== Расширенное troubleshooting

[#common-issues]
=== Типичные проблемы и решения

[#zigbee-network]
==== Нестабильность Zigbee сети

*Симптомы*: Высокий packet loss, частые disconnections
*Решение*: 
- Репозиционирование координатора
- Анализ RF interference на каналах 11-26
- Добавление Zigbee routers для улучшения mesh сети

[#mqtt-issues]
==== Проблемы с MQTT соединением

*Диагностика*:
+
[source,bash]
----
# Проверка качества соединения
mqtt-bench --broker tcp://broker:1883 --count 100 --interval 10
----

*Решение*: Настройка keepalive interval и retry mechanism

[#automation-issues]
==== Сценарии не выполняются

. Проверить правила в Rule Engine (AWS IoT Rules)
. Верифицировать корректность IAM permissions
. Анализировать CloudWatch Logs для Rule execution
